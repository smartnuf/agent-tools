# Agent Tools v0.2.0

Version 0.2 exposes the existing managed native-provider lifecycle through the
installed `agent-tools` command and makes document-processing Python libraries
optional. PyPI installed through `uv tool` is the supported application channel;
repository scripts remain development, CI, release and compatibility tools.

Publication is a separate release gate. Until it completes, public v0.1.2
remains available and the v0.2 commands below apply to the reviewed candidate.
Do not infer a published PyPI artifact from the source version alone.

## Installed interface and native capabilities

After installing a released v0.2 distribution through `uv tool`, use its
absolute launcher or explicitly opt into uv's shell update. No repository
checkout is required. With the launcher on PATH:

```sh
agent-tools tools list
agent-tools tools status
agent-tools install poppler --dry-run
agent-tools install poppler --allow-provider-mutation
```

Requests contain only named catalogue capabilities. Existing exact preferences
for those names are honored, unrelated enabled capabilities are not added, and
installation does not enable desired configuration. There is no package-name,
file, named-set or search interface. The same M3 catalogue, planning, explicit
authorization, execution, provenance, rediscovery and final verification layers
serve both installed CLI and compatibility workflows.

A dry run is read-only and needs no mutation flag. For execution, a nonempty
plan without `--allow-provider-mutation` is refused; already-satisfied
capabilities are verified no-ops without provenance writes. Reports separate host mutation from persistence and preserve partial or
uncertain recovery guidance. A produced dry-run plan returns 0 without execution,
final verification or persistence. For execution, statuses remain 0 for verified
success/no-op with successful or unnecessary persistence, 1 for an unsuccessful
operation, 2 for
invalid syntax/names and 130 for interruption. Do not blindly retry an uncertain
result. Native providers are external shared software, not owned by Agent Tools.

Windows WinGet App Execution Aliases retain their invocation path and receive
strict observed executable identity plus pre-action revalidation. Native reports
escape characters unsupported by a redirected output stream while retaining
full command evidence in provenance.

## Optional documents and migration

The core has no third-party Python runtime dependencies. Select the existing
PDF/image/Word/Excel library bundle explicitly for a released v0.2 version:

```sh
uv tool install --python 3.13 --reinstall 'smartnuf-agent-tools[documents]'
agent-tools doctor --documents
```

Plain `doctor` reports optional libraries separately; missing or broken optional
libraries do not affect its status. `doctor --documents` requires all seven
libraries to import. Both modes still check native Poppler and Ghostscript, so
an absent native tool can cause status 1. Neither command installs anything.
There are no document-processing subcommands, and `documents` is not a native
capability accepted by `agent-tools install`. Project interpreters remain
independent of uv's isolated tool environment.

An unpinned PyPI v0.1.2 installation can upgrade to the new core when v0.2 is
published. Explicitly select `[documents]` to retain the former library bundle.
Later upgrades retain selected extras and stored version constraints; exact pins
require explicit reinstall with the intended version. Return to core-only with:

```sh
uv tool install --python 3.13 --reinstall smartnuf-agent-tools
```

See the [README migration and rollback guidance](https://github.com/smartnuf/agent-tools/blob/main/README.md#pin-or-roll-back)
for the v0.1.1 direct-wheel path and checksum-bound rollback. Application
reinstall, rollback and removal do not remove native providers or user-owned
state. Explicitly restore an active managed integration before removing the
application or rolling back to a version without integration-removal support.
Failed transitions must not discard the previous valid installation or state.

3.11–3.13. External-preseed and simulated tests remain separately labelled.

## Boundary after v0.2

After v0.2 is qualified and published, choose a fresh Intent before expanding
scope. Named sets, `--from-file`, search, broader tool/rights research, TUI, MCP
and agent-specific recommendations remain future research. Alternative Agent
Tools distribution channels remain retired unless a new decision reopens them.

## Post-publication erratum — 2026-09-14

v0.2.0 is now stable on GitHub and published on PyPI. The publication caveat
above records the preparation state, not current availability. Desired-state
and Claude Code integration commands are included in the installed v0.2.0 CLI;
no repository checkout is required. The PyPI description contains a stale
sentence calling these commands main-only pending a release. This erratum
corrects that availability claim; it does not replace the immutable tag,
distribution files or PyPI metadata. See the
[qualification and known-limit record](https://github.com/smartnuf/agent-tools/blob/main/docs/plan/10-v0.2-productisation/11-release-qualification.md)
for exact publication evidence and pending disposition.
